解压后把两个 gguf 放到本目录 `models/` 下即可（`deploy.sh` 默认从那里取），并执行：

```bash

```

输出须与表 1 完全一致。若不一致，说明文件损坏或被替换，不应使用。

> **关于"自行完成转换量化且流程可复现"**：受提交包体积限制，**交付的 Q4_0 模型与原始 f16 权重都未随包**
> （2B 1.20 GB / 4B 2.54 GB；原始 f16 为 4 GB / 8 GB），均按 §2 从网盘获取。
> 转换与量化的**命令、参数与期望产物已全部固定**（流程见 `03_部署与复现` §4，产物见上表 1）。
> 评委有两种复核方式：**① 用表 1 的 SHA256 核验我们交付的模型**（无需原始权重）；
> **② 按 `03_部署与复现` §4 的命令从官方权重自行复跑**——同一工具链、同一参数下产物应与表 1 逐字节一致。

## 3 固定测试集

**表 3 测试集**

| 项目 | 内容 |
|---|---|
| 文件 | `工业监控固定测试集_v1.json` |
| 字节数 | 11,571 |
| SHA256 | `8fea798753d5890daa14fb566627dc65f74562bce538c1be4ae7790bffe617c6` |
| 题量 | 20 题 |
| 覆盖 | 报警处置、参数诊断、巡检报告、多轮追问、安全边界 |
| 判分 | 每题按关键词组命中率计分，命中 ≥0.8 记为通过 |

测试集为自建题集，全部公开。**判分脚本 `判分_固定测试集.py` 与题目一并提供**（只用 Python 标准库，板端 `python3` 直接可跑），评审可用同一口径复算：

```bash
# 需先按 03_部署与复现 起好 llama-server（-fa 0，端口 8097）
python3 判分_固定测试集.py --endpoint http://127.0.0.1:8097 \
    --testset 工业监控固定测试集_v1.json --rounds 5 --out 判分结果.json
```

判分口径：走 `/v1/chat/completions`（Qwen chat 模板）、`temperature=0`、`max_tokens=512`、默认关闭 thinking；
每题独立提问（不携带上一题历史），`must_contain` 是"关键词组"列表，**命中组数 / 总组数 ≥ 0.8 记为通过**；
脚本会输出逐题命中率、命中关键词与模型原文，便于逐条复核。题目内容为工业现场典型问法，不包含真实产线数据。

> 注意：0.8 是**很严**的门槛（四组关键词只允许漏一组）。表 4 的通过率就是在这一门槛下统计的；
> 单题命中率通常明显高于通过率，读表时不要把两者混用。

**表 4 质量结果**

| 模型 | 平均覆盖 | 通过率 |
|---|---:|---:|
| 2B 交付模型 | 0.75 | 45% |
| 4B 交付模型 | 0.875 | 70% |
| 第三方 4B（对照） | 0.871 | 13/20 |

> **2026-11-08 用本包脚本复算**（交付构建 `4436a9f4`、20 题 × 1 轮、thinking 关、测试集 v1.1）：
> **2B 覆盖 0.683、通过 35%；4B 覆盖 0.921、通过 80%**（4B 比上表更好）。
> 与上表的差异来自构建迭代——greedy 输出对措辞敏感，关键词判分随之后移。
> 已用**同一二进制**改 `GGML_CPU_CHUNK_MULT`（4 vs 16）做过对照：逐题命中完全一致，**分块补丁不是原因**；
> 差异来自**构建迭代与服务端启动参数**——greedy 输出对数值路径敏感，关键词判分随之后移
> （同一二进制仅更换 `-ub/-b/-fa` 三项即可改变逐题答案），故复算请严格按 §3 给出的参数启动服务。
> 注：本段四个复算值（0.683 / 0.921 / 35% / 80%）为现场复算的**参考值**，未登记为 claim、无独立证据文件，
> 不参与 `verify_claims.py` 校验；表 4 的 0.75 / 45% 与 0.875 / 70% 仍对应 C39 / C37。

## 4 复算用 prompt（首 token 时延）

技术报告表 2 的首 token 时延用下面三份**固定 prompt** 测出，文件随包提供，评委照同一份文件即可复算绝对值：

**表 5 复算用 prompt**

| 文件 | 字节 | 目标 token | 实测 `prompt_n` | SHA256 |
|---|---:|---:|---:|---|
| `prompts/ttft_128.txt` | 443 | 128 | 128 | `2e0cfda540ab9dbb3f4bde6cef1e349dfbdad10b620da061aa17fb97465c28f2` |
| `prompts/ttft_512.txt` | 1,551 | 512 | 513 | `d6002f1f75172763512212a937be82c85546a4d60814718feaf9ab616d8027cb` |
| `prompts/ttft_1024.txt` | 3,013 | 1,024 | 1,024 | `796319e12bb3636040311fd186b27d3d039de0fe004eb6fd6ff98a8c42763e42` |

三份都是同一份中文语料的**字符前缀**（`prompt_n` 由 `llama-server` 的 `timings.prompt_n` 反查标定）。

复算命令（服务按 03 节起好，`-fa 0`，端口 8097）：

```bash
python3 - <<'PY'
import json, urllib.request
p = open('prompts/ttft_128.txt', encoding='utf-8').read()   # 换成 512 / 1024 即可
req = urllib.request.Request(
    'http://127.0.0.1:8097/completion',
    data=json.dumps({'prompt': p, 'n_predict': 1,
                     'temperature': 0, 'cache_prompt': False}).encode(),
    headers={'Content-Type': 'application/json'})
t = json.load(urllib.request.urlopen(req, timeout=600))['timings']
print('prompt_n=%d  TTFT=%.2f s' % (t['prompt_n'], t['prompt_ms'] / 1000))
PY
```

**2B 交付构建实测**（同一块 8G 板、冷启动、3 次）：

| prompt | TTFT | 技术报告表 2 |
|---|---|---|
| 128 token | 5.02 / 5.20 / 5.27 s | 5.05 s |
| 512 token | 19.9 / 20.2 / 20.5 s | 19.49 s |
| 1024 token | 40.6 / 40.8 / 40.9 s | 40.15 s |

差异在 1—2% 以内（板间与冷启动噪声），**绝对值可复算**。4B 只需把 `-m` 换成 4B 模型，时序约为 2.4 倍。

*模型与测试集的 SHA256 以本文为准；取回文件后必须逐字节校验。*
